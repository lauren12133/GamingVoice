# GamingVoice · 使用手册

单文件 exe，双击即用。所有界面资源都编译进二进制，不需要附带 `src/web/`。

---

## 一、三个入口，同一套音频通路

程序启动后有三处可以操作，它们改的是同一份状态，所以从哪儿调都一样：

### 1. 原生窗口（启动即出现）

```
┌────────────────────────────────────────────┐
│ GamingVoice · 8 声道虚拟 7.1                │
│                                            │
│ 源（8 声道 loopback）                       │
│ [★ CABLE Input（8 声道） · 默认        ▾]  │
│ 输出（耳机）                                │
│ [耳机 (Realtek(R) Audio)（2 声道）      ▾]  │
│                                            │
│ [ 启动 ]  [ 打开完整面板 ]  [ 刷新设备 ]    │
│                                            │
│ 运行中  CABLE Input → 耳机                  │
│ 关闭本窗口只是收起，音频继续。               │
└────────────────────────────────────────────┘
```

- **关窗口 ≠ 退出**。点 × 只是把窗口收进托盘，音频继续跑 —— 否则误触一下就断音。
- 真正退出：托盘右键 →「退出 GamingVoice」，或窗口里没有退出按钮时用任务管理器。

### 2. 任务栏托盘

图标在通知区域（可能被折叠到 `^` 里，拖出来即可）：

| 操作 | 结果 |
|---|---|
| 左键双击 | 显示窗口 |
| 右键 | 菜单：显示控制窗口 / **启动音频** / **停止音频** / 打开完整面板 / 退出 |

「启动 / 停止」是灰显互斥的：正在跑时只能停，没跑时只能启。这一栏是给"打游戏时不想开窗口"准备的 ——
裁判暂停、接电话、切语音，右键两下就静音。

### 3. 网页面板（完整视图）

窗口里点「打开完整面板」，或直接访问 `http://127.0.0.1:8760/`。
8 个推子、声场图、预设都在这里。

## 二、面板怎么用

### 方向增益

| 元素 | 含义 |
|---|---|
| 中文名（前左 / 中置 …） | 该通道在 7.1 里的方位 |
| `FL · -30°` | 通道 id 与方位角（0° = 正前，正 = 右侧） |
| 推子 | 该方向增益，范围 **-30 ~ +20 dB**，步进 0.5 |
| 右侧数值 | 当前增益；被静音时显示"静音" |
| 电平条 | 该方向**增益后**的实时峰值（绿 → 黄 → 红） |
| 静音 | 该路直接 -60 dB（等价于关掉这个方向），再点一次恢复原值 |

**为什么能单独调**：增益加在 HRIR 卷积**之前**的 8 声道域。卷积完成后只剩 L/R，
8 路早已求和，方向信息只存在于双耳时频差里，那时再调只能改总音量。

### 声场图

- **半径** = 该方向增益（-30 dB 收到内圈，+20 dB 顶到外圈）
- **圆点亮度** = 该方向的实时电平，安静时变暗，出声时变亮
- 外圈中文是固定方位标签，不随增益移动（否则会互相压住）

### 预设

| 预设 | 效果 | 适合 |
|---|---|---|
| 平直 | 全 0 | 先听基线 |
| 战术·脚步 | 压前 -3 / 中置 -7，抬后 +12、侧 +4 | FPS 听脚步与换弹 |
| 影院 | 中置 +4、低频 +6 | 单机剧情、电影 |
| 只听前方 | 后四路 -18（保留一点方位感） | 嫌背后吵 |
| 后方静音 | 后四路 -60 | 极端只留前方 |

### 总补偿

整体输出增益（-30 ~ +12 dB），默认 **-6 dB**。
抬高多个方向后总能量会上去，用它在末端把峰值拉回来。

面板右上角出现「削波风险」时，说明某路 ≥ +12 dB 且总补偿 > -4 dB，或者双耳峰值已经顶到 0 dBFS。
这时要么降总补偿，要么把被抬的方向收一点。

### 主题与缩放

- **白天 / 黑夜**：按钮显示的是"点了会变成什么"。选择存在浏览器 localStorage，下次打开还生效。
- **A− / A+**：整体缩放四档（0.9 / 1 / 1.15 / 1.3）。1080p 屏上觉得字小就点 A+。

## 三、几个必须知道的设定

### 块长固定 480（10 ms），不再开放

界面上的块长下拉已注释掉（`src/web/index.html` 里能搜到），后端也只接受 480。

**你听到的"电流声"其实是一个 bug，不是小块的固有缺陷。** 旧实现里取数用 `HOP`（480）、
处理用可调 `block`（128）：一次 pop 480 帧只消费 128 帧，剩下 352 帧被丢掉，
于是每 10 ms 只有前 2.7 ms 有声音 —— 听感就是周期性的咔哒/电流声。

这个 bug 已修（`engine.rs` 的 `run_processor` 统一按 `BLOCK` 取数与处理），
理论上 128 也能正常工作。但竞技场景不应该再引入任何抖动，所以**默认仍锁 480**，
把开关注释保留，等以后有独占模式 / `IAudioClient3` 小周期这类更稳的方案再放开。

### 增益上限是 +20 dB

再高没有意义：单个方向 +20 dB 已经把"脚步声"推到贴脸，而 8 路同抬会立刻削波。
实战用法是一两个方向 +8~+12，其余 0 或负值。

### 设备名后面那个 `#2bd6f16` 是什么

**不是串口、不是设备序号**，是 Windows **MMDevice 端点 ID（GUID）的末 8 位十六进制**。
它只在拿不到设备友好名时才出现（驱动没暴露属性、被独占、权限异常）。

现在优先显示 `PKEY_Device_FriendlyName`，也就是"声音设置"里那个名字，
例如 `CABLE Input (VB-Audio Virtual Cable)`、`耳机 (Realtek(R) Audio)`。
取到了就不再显示 `#xxxx`。

## 四、常见问题

**Q：推子拖了没反应 / 只改总音量**
源端点不是 8 声道。面板上会有红字提示，`源` 下面也会写"非 8 声道"。
去 `声音设置 → 该设备 → 配置扬声器` 改成 7.1 环绕，然后点「刷新设备」。

**Q：启动报"源端点是 2 声道，不是 8 声道"**
同上。这是唯一会真正让功能失效的前提，其它问题都只是音色差异。

**Q：报"源端点采样率是 44100 Hz"**
去 `声音设置 → 该设备 → 高级 → 默认格式` 改成 **48000 Hz**。
不做隐式重采样是刻意的：重采样会改变 HRIR 的时频结构，方位会飘。

**Q：启动报"该设备可能被独占"**
另一个程序用独占模式占着端点（播放器、录音软件、某些游戏启动器）。
关掉它，或在它的设置里改成共享模式。

**Q：声音有咔哒声 / 断续**
先看面板上的「缓冲」和「欠载」。欠载在涨说明处理线程被抢了 CPU：
把游戏优先级调高、关掉后台占 CPU 的程序。若缓冲长期 0 ms 且欠载飙升，换一个输出端点试试。

**Q：方位感很弱，听不出前后**
两件事：① 必须戴耳机；② 合成 HRIR 的前后区分本来就弱于实测数据（前后在双耳线索上高度相似，
人靠耳廓的频谱陷波分辨，球头模型没有耳廓）。想要更强的方位，见下一节换 HRIR。

**Q：能不能和 Dolby Access 一起用**
可以，但**让 Dolby 做双耳化**：在 Windows 里给耳机开 Dolby Atmos for Headphones，
GamingVoice 这边只做 8 声道增益（相当于它替掉了 Equalizer APO 的角色）。
两个 HRTF 串起来不是更好，是更糊 —— 声场变窄、定位发虚、低频叠加。

## 五、换成真实 HRIR（可选）

现在用的是 Woodworth 球头模型合成的 HRIR（`engine.rs` 的 `synth_hrir`）：
双耳时差 + 头影低通 + 4 ms 早期反射，没有耳廓。它的价值是"能听出方向变了"，
不是"和专业 HRTF 一样准"。

要换真实数据：把一组 16 声道 HRIR WAV 按 `dsp/surround/hrir.rs` 约定的
`(声道, 耳)` 排布喂进去（解析器在 `dsp/surround/wav.rs`，支持 PCM16/24/32、float32/64、
EXTENSIBLE），然后把 `run_processor` 里的 `synth_hrir(...)` 换成 `Hrir::from_wav(...)`。

> HeSuVi 的 `hrir/*.wav` 具体声道排布没有书面规范，不同版本不一样。
> 接之前先用单个冲激测一遍左右耳对应的通道，别直接套。

## 六、HTTP 接口（想写脚本 / 自动化时用）

只监听 `127.0.0.1:8760`，不对外。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/state` | 全量状态：端点列表、参数、电平、欠载 |
| POST | `/api/params` | 改 `gains_db` / `delays_ms` / `makeup_db` |
| POST | `/api/start` | body `{"source":"<端点id>","sink":"<端点id>"}` |
| POST | `/api/stop` | 停止 |
| POST | `/api/refresh` | 重新枚举音频端点 |

例：把后左后右抬 10 dB

```bash
curl -X POST http://127.0.0.1:8760/api/params \
  -H 'Content-Type: application/json' \
  -d '{"gains_db":[0,0,0,0,10,10,0,0]}'
```

`block` 字段仍然接受，但会被忽略并返回 `note`（块长锁定 480）。

## 七、源码地图

| 文件 | 职责 |
|---|---|
| `src/main.rs` | HTTP 服务、状态聚合、启动/停止（含设备打开的超时与错误信息） |
| `src/engine.rs` | 处理线程：环 → 8 声道总线 → 增益 → HRIR → 双耳；`synth_hrir` |
| `src/audio_windows.rs` | WASAPI：端点枚举 + 真实设备名、loopback 采集、事件驱动渲染 |
| `src/audio_stub.rs` | 非 Windows 占位（让 `cargo test` 能跑） |
| `src/gui_windows.rs` | 原生窗口、托盘、菜单、控件状态刷新 |
| `src/web/` | 面板（编译进 exe：`include_str!`） |
| `src/dsp.rs` | 把共享 DSP 模块接进来（`#[path]`，不复制） |
| `examples/eq_bench.rs` | EQ 段数的 CPU 实测（见 `../docs/EQ-评估.md`） |

## 八、自检清单（换机器 / 换声卡时按顺序过一遍）

1. `声音设置 → 播放` 里能看到 CABLE Input，且配置为 **7.1 环绕**；
2. 该端点采样率是 **48000 Hz**；
3. 游戏输出设备 = CABLE Input，音频输出模式 = 7.1 / 家庭影院；
4. GamingVoice 源选 CABLE Input（前面有 ★），输出选耳机；
5. 点启动，面板「源」下面显示"8 声道 · 可作 7.1 源"；
6. 放个能听出方向的素材，拖「后左」推子，只有后方变化 → 全链路通了。
